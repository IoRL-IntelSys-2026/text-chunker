# Шаблон: отчёт о качестве (`quality_report.md`)

Файл лежит рядом с коллекцией: `data/index/<collection>/quality_report.md`.
Его пишет `python ingest.py quality`. Ниже — порядок блоков и что значит каждая цифра.

## Снимок и коллекция

| Поле | Что значит |
| --- | --- |
| snapshot_id | Какой снимок K1 нарезали |
| collection | Имя коллекции / папки индекса |
| документов в manifest | Сколько строк в описи снимка (или уникальных doc_id, если описи нет) |
| статусы документов | Сколько документов ok / error / … (на mdd без convert_report — все ok) |

## Чанки и токены

| Поле | Что значит |
| --- | --- |
| чанков всего | Число строк в `chunks.jsonl` |
| токены min / медиана / p95 / max | Длина поля `text` в токенах bge-m3 |
| гистограмма | Распределение длин по корзинам |
| отброшено коротких | Сколько кусков выкинули как слишком короткие (если шаг это считал) |
| слито заголовков | Сколько заголовков склеили со следующим куском |

## Повторы

| Поле | Что значит |
| --- | --- |
| dup_ratio | Σ(\|g\| − 1) / N: доля «лишних» копий одинакового текста между разными документами |
| топ-20 групп | Самые большие группы одинаковых чанков с примерами URL |
| баг-репорт PRS | На РУДН при dup_ratio ≥ 2 %; на mdd ненулевое значение только фиксируем |

## Языки, типы, время, версии

Кратко: сколько документов по `lang` и `content_type`, сколько секунд заняли шаги (если замеряли), какие `chunker` и `embedding_model`.

## Ворота K2

Локальная проверка `chunks.jsonl` перед алиасом: схема `k2.v1`, обязательные поля, `has_generated_text = false`, срезы текста совпадают со страницами снимка, `doc_content_hash` совпадает с manifest.

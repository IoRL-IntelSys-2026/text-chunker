# RAG SYSTEM

Это RAG-система: ответ собирается не из памяти модели, а из найденных кусков документов. Человек задаёт вопрос, программа ищет близкие фрагменты и просит модель написать ответ только по ним.

Система сделана на учебном архиве MultiDoc2Dial: 488 готовых английских страниц про права и регистрацию, социальное страхование, дела ветеранов и помощь студентам. Архив нужен раньше сайта университета, чтобы собрать и проверить всю цепочку на известных текстах. Документы приведены к снимку, нарезаны на фрагменты, посчитаны векторы и загружены в Qdrant.

## Что сделано

1. **Снимок `mdd_v1`.** Из `data/cache/multidoc2dial.zip` прочитаны 488 документов, zip на диск не распаковывался. Текст сохранён как есть. У каждого документа есть адрес `mdd://`, номер `doc_id`, файл страницы, файл разделов и строка в описи.
2. **Нарезка.** Фрагменты режутся по разделам: лимит 512 токенов, перекрытие 64, минимум 24. Получилось 7149 фрагментов в `chunks.jsonl`.
3. **Векторы.** Модель `BAAI/bge-m3` считает их по полю `embed_text`. В это поле собираются заголовок документа, заголовки раздела и текст фрагмента. По этой строке получаются плотный вектор на 1024 числа и разреженный вектор слов. Они лежат в `vectors.jsonl`, в том же порядке, что и фрагменты.
4. **База.** Коллекция Qdrant Cloud `mdd_chunks_v1`: 7149 точек, номер точки равен `chunk_id`.
5. **Поиск и ответ.** `retrieve.py` ищет по смыслу и по словам и склеивает списки. `answer.py` отдаёт найденные фрагменты модели `Qwen/Qwen2.5-0.5B-Instruct`. Модель грузится через Hugging Face `transformers` на видеокарту, сервера vLLM нет.


## Как устроено

```text
архив zip
  → снимок data/snapshots/mdd_v1
  → фрагменты data/index/mdd_chunks_v1/chunks.jsonl
  → векторы data/index/mdd_chunks_v1/vectors.jsonl
  → коллекция Qdrant mdd_chunks_v1
  → retrieve.py
  → answer.py
```

Снимок, нарезка и `.env` в git не входят. В репозитории лежат код, тесты, конфиг нарезки и копия архива.

Подробный разбор одного короткого документа: `docs/one_document_path.md`. Пояснение к снимку: `docs/mdd_v1_explained.md`.

## Запуск поиска

В `.env` нужны адрес кластера и ключ:

```text
QDRANT_URL=...
QDRANT_API_KEY=...
```

Поиск с ответом в консоли:

```text
python retrieve.py "How do I apply for disability benefits?"
```

Без аргумента скрипт спросит строку сам. Нужны видеокарта и уже загруженные точки в коллекции `mdd_chunks_v1`. Модель ответа при первом запуске скачивается с Hugging Face.

Проверки:

```text
python -m pytest
```

## Архив

`data/cache/multidoc2dial.zip` — официальная копия архива MultiDoc2Dial, около 6,6 МБ. Архив не распаковывать: документы читаются из zip в памяти.

Источник: https://doc2dial.github.io/multidoc2dial/file/multidoc2dial.zip

Цитирование: Feng et al., «MultiDoc2Dial: Modeling Dialogues Grounded in Multiple Documents», EMNLP 2021.
